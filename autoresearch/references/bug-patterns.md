# Bug Patterns — 반복되는 결함 헌팅 체크리스트

TARGET/RESEARCH 단계에서 빠르게 후보를 찾기 위한 실증 기반 패턴 목록. 이 저장소를
자가개선하며 실제로 잡은 결함 13건을 일반화한 것이라, "어디를 먼저 볼지"의 사전 확률을 높인다.

각 패턴은 **냄새(어디서 grep) → 왜 터지나 → 검증법** 순으로 본다. 한 패턴에서 하나를 고치면
같은 패턴의 자매 위치를 함께 훑는 것이 효율적이다(예: 캐시 무효화 한 곳을 고치면 모든
상태변경 메서드를 점검).

## 1. 디코딩 크래시 (decode without errors=)

- **냄새**: `.decode("utf-8")`, `bytes(...).decode()`, `json.loads(<외부문자열>)`, `int(...)`,
  `float(...)` 가 외부/사용자 데이터에 직접 걸릴 때.
- **왜**: 실데이터는 비UTF-8 charset, 빈 문자열, `-`/`N/A` 같은 비숫자가 섞인다. 한 건이
  예외를 던지면 배치 전체가 죽는다.
- **고침**: `errors="replace"`(텍스트 표시), 바이너리 폴백(첨부), `try/except`로 0/빈값 격하
  (배치 파싱). **단일 행 결함이 전체를 죽이지 않게** 하는 게 핵심.
- **검증**: 0xff 바이트/빈 문자열/`-` 입력으로 재현 → 수정 후 크래시 없이 진행.
- (이 저장소 실례: parser 금액, classifier 시간, gmail 본문, 첨부 텍스트)

## 2. 캐시 무효화 누락 (mutation without invalidation)

- **냄새**: 상태를 바꾸는 메서드(send/modify/trash/delete/create/update/label)인데 끝에서
  `invalidate_*` 호출이 없다. 한 메서드만 호출하고 자매 메서드는 빠뜨린 **비대칭**.
- **왜**: 변경 후에도 캐시가 옛 값을 주어, 목록/라벨/메시지가 stale.
- **고침**: 같은 클래스의 모든 mutator가 동일하게 무효화하도록 맞춘다(한 곳을 기준점으로).
- **검증**: 캐시를 채운 뒤 mutator 호출 → 캐시가 비워졌는지(또는 갱신) 확인.
- (실례: modify/send_draft/label CRUD 가 목록·라벨 캐시 무효화 누락)

## 3. 공유 키/파일에 다른 의미 저장 (cache poisoning)

- **냄새**: 서로 다른 형식·범위의 데이터가 **같은 캐시 키/파일**을 쓴다(예: metadata vs full).
- **왜**: 좁은 데이터가 넓은 데이터를 덮어쓰면, 넓은 조회가 빈/부분 데이터를 받는다.
- **고침**: 상위집합만 저장하거나 키를 분리한다.
- **검증**: 좁은 조회 → 넓은 조회 순서에서 넓은 데이터가 온전한지 확인(양방향).

## 4. 하드코딩된 경로/이름 (portability)

- **냄새**: 절대경로(`/Users/...`), 특정 사람 이름이 코드/패턴에 박혀 있다.
- **왜**: 작성자 외 사용자·CI에서 동작하지 않는다.
- **고침**: config 오버라이드 + 옵션 파라미터(기본값은 기존 상수 → 하위호환).
- **검증**: 다른 값으로 동작 확인 + 기존 값 불변 확인.

## 5. 경계/오버플로 (index, range, off-by)

- **냄새**: `chr(ord("A")+i)`, `range(0, n, step)` 에서 step이 변수, 수동 인덱스 산술,
  `[0]`/`[-1]` 무방비 접근.
- **왜**: 입력이 경계를 넘으면(27번째 열, step=0, 빈 리스트) 잘못된 값/예외.
- **고침**: 라이브러리 헬퍼(`get_column_letter`), 하한/상한 클램프(`max(1, min(...))`), 가드.
- **검증**: 경계값(26/27, 0, 빈) 입력으로 재현 → 수정.

## 6. 상한 계약 위반 (cap order)

- **냄새**: 캡(`min(x, max)`) 이후에 곱셈/지터/조정이 더 일어난다.
- **왜**: 최종 값이 명시한 상한을 넘는다(지수 백오프 지터 등).
- **고침**: 모든 조정 **이후** 마지막에 캡.
- **검증**: 다수 샘플의 최대값이 상한 이하인지 통계 확인.

## 7. 재현 불가능한 테스트 (hermeticity)

- **냄새**: 테스트가 로컬 절대경로/실파일/네트워크에 의존.
- **왜**: 신선한 클론·CI에서 실패하거나 검증 신호가 없다.
- **고침**: 합성 픽스처(생성기), 의존성 주입(파라미터), 페이크 서비스, 모듈 path-load로
  무거운 import 회피. CI로 게이트.
- **검증**: 깨끗한 환경(새 venv/CI)에서 통과.

---

**메타 규칙**: 한 패턴의 결함을 고쳤으면, **같은 패턴의 모든 형제 위치를 즉시 grep**해 일괄
점검하라. 결함은 무리지어 산다 — 하나를 잡으면 사촌이 근처에 있다.

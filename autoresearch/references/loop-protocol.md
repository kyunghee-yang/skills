# Loop Protocol — 상태기계 · 멈춤 · 원장

오토리서치 루프의 정확한 동작을 정의한다. SKILL.md의 7단계를 상태기계로 형식화한 것.

## 상태기계

```
        ┌────────────────────────────────────────────────┐
        ▼                                                 │
  [STATE] → [TARGET] → [RESEARCH] → [CANDIDATE] → [AB-EVAL] → [DECIDE]
                                                              │
                          ┌───────────────────────────────────┤
                          ▼ (채택)                             ▼ (폐기)
                       [VERIFY]                          A안 복원 + 학습기록
                          │                                    │
                  ┌───────┴──────┐                             │
                  ▼ (통과)        ▼ (실패)                       │
               [SHIP]         A안 복원 + 학습기록                 │
                  │                │                            │
                  └────────────────┴────────────────────────────┘
                          │
                          ▼
                   멈춤 신호?  ──예──▶ [STOP]
                          │
                          아니오 → 후보 있음? ──아니오──▶ 고갈 방지(탐색 확대)
                          │                                    │
                          └─────────────── 예 ─────────────────┴──▶ [STATE]
```

## 멈춤 판정 (STOP)

멈추는 **유일한** 정상 조건은 사용자의 명시적 중단 지시다. 다음 표현을 멈춤으로 해석한다:

- 한국어: "멈춰", "그만", "중지", "중단", "스톱", "이제 됐어", "그만해"
- 영어: "stop", "halt", "that's enough", "you can stop"

다음은 멈춤이 **아니다** (계속한다):

- 한 이터레이션 완료 후의 정적 → 곧바로 다음 이터레이션 시작
- "잘했어", "좋아" 같은 긍정 피드백 → 격려이지 중단이 아님
- 후보 고갈 → 탐색 범위를 넓힌다(아래)

예외적으로 진행 전 사용자 확인이 필요한 경우(돌이키기 어려운/외부로 나가는 행동)에는
`AskUserQuestion`으로 묻고, 답을 기다리는 동안에도 다른 비파괴적 타겟으로 이터레이션을 이어간다.

## 고갈 방지 (Exhaustion → Broaden)

후보가 없다고 멈추지 않는다. 다음 순서로 탐색 축을 회전시킨다:

1. **타겟 회전**: 현재 디렉터리/스킬 → 다음 디렉터리/스킬
2. **리서치 확대**: 인접 도메인, 최신 라이브러리 릴리스 노트, 경쟁 오픈소스와의 벤치마크
3. **메타 개선**: 오토리서치 스킬 자체(지표 정의, 스크립트, 레퍼런스 품질) 개선
4. **측정 확충**: 평가 불가였던 영역에 테스트/평가 케이스를 추가해 다음 사이클의 A/B 가능화

세 바퀴를 돌아도 의미 있는 후보가 없으면, 현재까지의 누적 개선을 요약 보고하고 **저강도 유지
모드**로 전환한다(새 정보/릴리스가 생기면 다시 능동 개선). 그래도 멈추지는 않는다.

## 원장 스키마 (`.autoresearch/ledger.json`)

```json
{
  "branch": "claude/auto-research-capability-tRWtN",
  "started_at": "2026-06-04T00:00:00Z",
  "iteration": 7,
  "iterations": [
    {
      "n": 7,
      "target": "expense-report/src/classify.py",
      "hypothesis": "R5 카페 매칭에 정규식 대신 키워드셋을 쓰면 오탐 줄고 30% 빠름",
      "research": ["내부 프로파일링", "https://example/regex-vs-set"],
      "ab": {"metric": "오탐률", "a": 0.12, "b": 0.04, "winner": "B"},
      "decision": "adopted",
      "verify": "tests/test_classify.py 18/18 통과",
      "commit": "a1b2c3d",
      "ts": "2026-06-04T01:23:00Z"
    }
  ],
  "discarded_hypotheses": [
    "분류를 LLM 호출로 대체 → 느리고 비결정적, A 우세로 폐기"
  ]
}
```

- `iteration`: 다음에 시작할 번호.
- `discarded_hypotheses`: 폐기된 가설. **중복 시도 방지용**으로 매번 0단계에서 읽는다.
- 원장은 git에 커밋하지 않는다(로컬 진행상태). `.gitignore`에 `.autoresearch/` 추가.

## 이터레이션 크기 규율

- 한 이터레이션 = 한 가설 = 한 커밋. 가설이 둘 이상이면 쪼갠다.
- 한 변경이 30분 이상의 작업으로 보이면 너무 크다 — 더 작은 검증 가능한 조각으로 분해.
- "리팩터링 전체"처럼 A/B가 불가능한 큰 변경은 사용자 확인 후, 측정 가능한 단위로 나눠 진행.
